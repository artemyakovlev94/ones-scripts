# `src/workflows/create_or_update_database.os`

Workflow создаёт или обновляет файловую информационную базу ветки, загружает конфигурацию и расширения, регистрирует базу в списке 1С и запускает клиент.

## Зависимости

- `src/lib/process.os`;
- `src/lib/files.os`;
- `src/lib/ibases.os`;
- `src/lib/one_c_database.os`;
- `src/lib/one_c_extensions.os`;
- Vanessa Runner 3.x (`vrunner`);
- `ibcmd.exe` требуемой версии и разрядности платформы 1С.

## Публичный интерфейс

### `Запустить(ИмяВетки, ПутьРепозитория, ИмяБазы, ПутьКБазе, ПараметрыОкружения, Расширения, КореньПроекта)`

Выполняет следующие этапы:

1. Проверяет входные данные, каталоги исходников и файлы расширений.
2. Использует переданные имя и путь базы. Для незаполненного имени используется имя ветки, для незаполненного пути — `ONE_C_BASES_PATH\ИмяВетки`. Отсутствующая база создаётся командой `vrunner infobase init --ibcmd`.
3. Сразу после проверки или создания базы создаёт запись в `%APPDATA%\1C\1CEStart\ibases.v8i` внутри папки `ONE_C_IBASES_FOLDER\_ИмяВетки`. Если имя базы передано явно и уже найдено во всём файле, регистрация пропускается без изменений. Для вычисленного имени сохраняется обычная логика разрешения конфликтов суффиксами.
4. Для существующей базы загружает конфигурацию через `ibcmd`.
5. Загружает тестовое расширение напрямую из исходников командой `vrunner cfe load`, без создания промежуточного CFE, затем отключает ограничения расширения.
6. Загружает расширения из переданного массива структур `name,path` и отключает для каждого безопасный режим и защиту от опасных действий.
7. Запускает клиент новой или существующей базы через `vrunner run enterprise --no-wait`. Workflow завершается сразу после запуска и не ожидает закрытия клиента.

При ошибке любого этапа workflow прекращает выполнение и вызывает исключение с названием этапа.

Vanessa Runner 3.x не использует кэш списка баз; удалённый параметр `--nocacheuse` не передаётся. Регистрацией в `ibases.v8i` управляет только `src/lib/ibases.os`.

Для существующей базы workflow передаёт `ONE_C_INFOBASE_USER` и `ONE_C_INFOBASE_PASSWORD` в `ibcmd` как `--user` и `--password`, а в Vanessa Automation — как `--db-user` и `--db-pwd`. При создании новой базы параметры авторизации не передаются.

После загрузки расширения workflow выполняет `ibcmd infobase config extension update` с параметрами `--safe-mode=no` и `--unsafe-action-protection=no`. Для тестового расширения также передаётся `--used-in-distributed-infobase=no`.

Workflow отвечает только за проверку параметров и последовательность этапов. Формирование и выполнение команд платформы вынесено в `src/lib/one_c_database.os` и `src/lib/one_c_extensions.os`.

### `ЗапуститьИзБазыДляСоздания(ИмяВетки, ПутьРепозитория, ИмяБазы, ПутьКБазе, ПараметрыОкружения, Расширения, КореньПроекта, ПутьКБазеДляСоздания)`

Проверяет, что `ПутьКБазеДляСоздания` заполнен и содержит файл `1Cv8.1CD`, после чего запускает ту же цепочку обработки. Если в целевом каталоге нет `1Cv8.1CD`, исходный файл копируется туда. Скопированная база обрабатывается как существующая: исходники основной конфигурации загружаются через `ibcmd`, а для подключения используются `ONE_C_INFOBASE_USER` и `ONE_C_INFOBASE_PASSWORD`.

### `ЗагрузитьТестовоеРасширениеВСуществующуюБазу(ИмяВетки, ПутьРепозитория, ПутьКБазе, ПараметрыОкружения, КореньПроекта)`

Требует существующий файл `1Cv8.1CD` в целевом каталоге, загружает расширение напрямую из исходников `REPOSITORY_PATH_CFE_TEST` командой `vrunner cfe load`, отключает безопасный режим, защиту от опасных действий и использование в распределённой базе. Метод не загружает основную конфигурацию, не регистрирует базу в `ibases.v8i` и не запускает клиент.

### `ЗагрузитьКонфигурациюВСуществующуюБазу(ИмяВетки, ПутьРепозитория, ПутьКБазе, ПараметрыОкружения)`

Требует существующий файл `1Cv8.1CD` в целевом каталоге, импортирует исходники основной конфигурации из `REPOSITORY_PATH_CF` командой `ibcmd infobase config import` и обновляет конфигурацию базы данных через `vrunner infobase update --ibcmd`. Метод не загружает расширения, не изменяет `ibases.v8i` и не запускает клиент.

ИмяВетки означает имя задачи, ПутьРепозитория — корень исходников. Пользовательские точки входа определяют их через [repository_context](repository_context.md).
